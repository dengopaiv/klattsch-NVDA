# How klattsch works today

The state of the JavaScript engine as of 0.8.0, written down because it is the
thing being ported. Every file path and number here is from the source, not from
the README.

## The whole engine is about a thousand lines

| File | Lines | What it is |
|---|---|---|
| `src/engine/dsp.js` | 80 | Bandpass biquad, glottal pulse, noise, soft clip |
| `src/engine/synth-core.js` | 190 | `FormantSynth` — the sample loop |
| `src/engine/sequencer.js` | 514 | Tokenizer and schedule compiler |
| `src/engine/banks/index.js` | 103 | Phoneme-bank registry, `extends` resolution |
| `src/engine/wav.js` | 74 | RIFF/WAVE encoder with a LIST INFO chunk |
| `src/engine/index.js` | 25 | Public surface |
| `src/engine/phonemes.js` | 12 | Legacy re-export of the default bank |
| `src/formant-worklet.js` | 59 | AudioWorklet shim, one `FormantSynth` per voice |

Plus `src/engine/banks/bundled.js` (762 lines, generated by `tools/build-banks.js`
from the three JSON banks), `src/engine/pronounce.js` (55 lines, CMU dictionary
lookup, optional dependency) and `src/engine/kana.js` (185 lines, kana/romaji to
phonemes). `src/highlight.js` (215 lines) is editor sugar and is not part of the
engine.

Zero runtime dependencies. The DSP has no dependency on any audio API — the
worklet is a wrapper, and `bin/klattsch.mjs` renders offline through the same
code.

## The two halves

```
    phoneme string
         |
         |  tokenize()               sequencer.js
         v
     [ tokens ]
         |
         |  compile()                sequencer.js
         v
  [ schedule events ]   { atMs, target, transitionMs }
         |
         |  FormantSynth.process()   synth-core.js
         v
    Float32 samples
```

The halves are genuinely decoupled: the compiler emits a plain array of
timestamped parameter targets, and anything at all can interpret it. Upstream
leans on that with `[engine=NAME]` and uppercase bracket directives, which the
compiler records but `FormantSynth` ignores. For the C port this matters a lot:
**the compiler and the synth can be ported and verified independently.**

## The signal path, one sample at a time

`FormantSynth.process()` runs this per sample. There is no frame-based block
processing and no vectorization; every parameter is updated at sample rate. It
is the simplest possible structure and also the most expensive one.

1. **Drain the schedule.** Any event whose `atSample <= sampleCounter` sets
   `target[k]` for the keys it carries and recomputes `increment[k] =
   (target[k] - current[k]) / N` for *all* 19 parameters, where `N` is the
   event's transition in samples.
2. **Interpolate.** If a transition is running, `current[k] += increment[k]`
   for all 19 parameters; on the last sample, snap `current[k] = target[k]`.
   Linear, per-sample, no smoothing.
3. **Vibrato.** `effF0 = F0 + vibratoDepth * sin(vibratoPhase)`, phase advanced
   by `2*pi*vibratoRate/sr` and wrapped.
4. **Tremolo.** `tremoloMod = 1 - tremoloDepth * (0.5 + 0.5*sin(tremoloPhase))`.
   Note this is a *unipolar* modulator: at depth 1 it sweeps 1 down to 0, and it
   never exceeds 1.
5. **Excitation.** Three sources mixed by `voicing` (clamped 0..1) and
   `aspiration`:

   ```
   voicedGain = 1 - aspiration * 0.85
   exc = voicing * glottalPulse(phase, effort) * voicedGain
       + (1 - voicing) * noise * 0.35
       + aspiration * noise * 0.5
   ```

   `noise` is a 32-bit xorshift LFSR (shifts 13, 17, 5) divided by `2^31`, so
   the range is [-1, 1) from the *signed* interpretation of the state.
   `glottalPhase` advances by `effF0/sr` and wraps by subtracting its floor.
6. **Filtering.** Three constant-skirt-gain bandpass biquads (RBJ cookbook),
   each fed the same excitation, coefficients recomputed only when the pair
   (f, bw) changes — which, during a transition, is every sample.
   `y = (bp1*A1 + bp2*A2 + bp3*A3) * gain * tremoloMod`.
   Purely parallel. There is no cascade path.
7. **Spectral tilt.** A one-zero filter: `tilted = y - tilt * tiltPrev`, with
   `tiltPrev` the previous *untilted* `y`. Positive tilt is a differentiator
   (brighter); negative is a leaky integrator (darker).
8. **Soft clip.** Linear to ±0.85, then `T + (1-T)*e/(e+1)` above it.

### The glottal pulse

`glottalPulse(phase, effort)` is the derivative of a Rosenberg pulse: two
half-sine lobes over a phase normalized to [0, 1).

| Region | Value |
|---|---|
| `phase < Tp` | `0.1 * 0.5 * (pi/Tp) * sin(pi*phase/Tp)` |
| `Tp <= phase < Tp+Tn` | `-0.1 * (pi/(2*Tn)) * sin(pi*(phase-Tp)/(2*Tn))` |
| otherwise | `0` (the closed phase) |

`effort` 0..1 maps `Tp: 0.5 -> 0.3` and `Tn: 0.25 -> 0.08`. So effort is an
open-quotient and a closure-sharpness control in one knob, and the closed phase
grows from 25% to 62% of the period as effort rises. The `0.1` is a
normalization constant chosen so the tense-end peak lands near unity.

No LF model, no jitter, no shimmer, no flutter, no diplophonia. The pulse is
deterministic and perfectly periodic.

## The compiler

`tokenize()` normalizes (NFKC, strips zero-width characters, folds a table of
Greek and Cyrillic homoglyphs to Latin), strips `#` line comments and `/* */`
block comments, splits on whitespace, and classifies each part. `'` and `!`
retroactively mark the most recent phoneme token as stressed.

`compile()` partitions the token stream at each `[voice=N]` marker into
sections and compiles each section independently from a fresh initial state via
`compileSection()`. Voice 0 is mirrored onto the top-level
`schedule`/`phrases`/`engine`; `totalMs` is the maximum across sections.

`compileSection()` walks a single cursor, `timeMs`, and pushes schedule events.
The running state it carries is: `f0`, `rate`, `scale`, `vibrato`,
`vibratoRate`, `tremolo`, `tremoloRate`, `aspiration`, `tilt`, `effort`, the
active phoneme bank, the engine name, and an `extras` bag of uppercase
directives. Every emitted target is the phoneme's fields, then `extras`, then
the running voice state.

### Phoneme timing

A phoneme gets a slot of `rate` ms, times 1.5 if stressed. Inside `(...)`, the
whole group shares one `rate` slot split evenly. Then the slot is filled by one
of four shapes:

| Shape | Condition | Layout |
|---|---|---|
| **Stop** | `p.isStop` | silence for `slot - burst`, then a burst of `min(25, slot*0.3)` ms |
| **Glide** | `p.glideTo` | 25% onset / 50% glide to the endpoint / 25% offset |
| **Pitch move** | `pitchDelta != 0` | target at 25% in, then a second target ramped over 60% |
| **Steady** | otherwise | one target, transition `min(35, slot*0.4)`, hold the rest |

Sticky pitch (`AY+15`) adds to the running `f0` after the phoneme; transient
pitch (`AE(+40)`) does not. Every section ends with a `fadeOutMs` silence and
`trailOffMs` of tail.

### The constants nobody can reach

`DEFAULTS` in `sequencer.js` is `Object.freeze`d, and most of it has no
directive:

| Constant | Value | Reachable? |
|---|---|---|
| `baseF0` | 120 Hz | yes, via `b` |
| `rate` | 110 ms | yes, via `r` |
| `stressDurationFactor` | 1.5 | **frozen** |
| `stressF0Lift` | 8 Hz | **frozen** |
| `stopBurstMs` | 25 | **frozen** |
| `defaultTransitionMs` | 35 | **frozen** |
| `sentenceFinalHoldMs` | 0 | **frozen** |
| `fadeOutMs` | 100 | **frozen** |
| `trailOffMs` | 150 | **frozen** |
| `PAUSE_MS` | `,` 100 / `;` 200 / `.` 300 | **frozen** |

Plus the shape ratios in `renderPhoneme` (0.25/0.50/0.25, 0.3, 0.4, 0.6, and
the 5/20/25 ms transition caps), the mix constants in `synth-core.js` (0.85,
0.35, 0.5), the soft-clip threshold, and the glottal normalization.

This is the single largest finding of the study: **most of what shapes
klattsch's voice is not a parameter.** Exposing these is the substance of the
GUI generator, not a nice-to-have — see [GENERATOR.md](GENERATOR.md).

## The parameter surface as it stands

**Per-target, interpolated (19)** — `PARAMS` in `synth-core.js`:
`F0`, `voicing`, `F1`, `BW1`, `A1`, `F2`, `BW2`, `A2`, `F3`, `BW3`, `A3`,
`gain`, `vibratoDepth`, `vibratoRate`, `tremoloDepth`, `tremoloRate`,
`aspiration`, `tilt`, `effort`.

**Directives** — compact single letters, optionally `=absolute` or
`+`/`-` relative; a bare letter resets to the initial value:

| Letter | Parameter | Letter | Parameter |
|---|---|---|---|
| `b` | base F0 (or `bC#4`, a note name) | `m` | tremolo depth |
| `r` | rate, ms per phoneme | `n` | tremolo rate |
| `p` | pause, ms | `h` | aspiration |
| `s` | formant frequency scale | `t` | spectral tilt |
| `v` | vibrato depth | `g` | effort |
| `w` | vibrato rate | | |

**Bracket forms**: `[bank=NAME]`, `[bank]`, `[engine=NAME]`, `[engine]`,
`[voice=N]`, and any `[UPPERCASE=value]` recorded verbatim into `extras`.

**Per phoneme, in a bank**: `voicing`, `F1`, `F2`, `F3`, `BW1`, `BW2`, `BW3`,
`A1`, `A2`, `A3`, `isStop`, `glideTo{F1,F2,F3}`. Banks may carry `F4`/`BW4` and
up; the compiler scales them by `s` but `FormantSynth` ignores them.

## Banks

`klatt1980-en` (40 phonemes, Klatt 1980 Tables II and III), `ja-mokhtari-2000`,
`ja-hecko-2026`. A bank may `extends` another; the registry resolves and caches
the merge, and a `null` entry deletes an inherited phoneme. The JSON is the
source of truth and `tools/build-banks.js` regenerates `bundled.js`.

## What has no answer here at all

- **Text.** klattsch takes phonemes. `pronounce.js` is a CMU dictionary lookup
  behind an *optional* npm dependency, with no letter-to-sound fallback, no
  number or abbreviation handling, and no homograph disambiguation. For a
  screen reader this is the blocking gap, not the DSP.
- **Duration.** Every phoneme is `rate` ms. A stop and a diphthong get the same
  slot. No intrinsic durations, no clause-final lengthening.
- **Coarticulation.** Only the fixed `glideTo` endpoint baked into diphthongs.
  No locus equations, no context-dependent transitions.
